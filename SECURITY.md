# Безопасность

Exchange credentials и MCP-токены остаются на машине пользователя в приватном
`.env`. Для обычного локального запуска сервер слушает только `127.0.0.1`.
Публикация через сеть требует собственного HTTPS и контроля доступа.

Не прикладывать к issues пароли, заголовки Authorization, письма, вложения,
календарные данные, подписанные ссылки или каталог `DATA_DIR`. Использовать
синтетический пример и обезличенные сообщения об ошибках.

Права Exchange остаются у провайдера. Для записи используются отдельный токен,
явные группы операций, подписанный план и журнал результатов. После неизвестного
исхода сначала сверить результат, затем решать, нужен ли повтор.
