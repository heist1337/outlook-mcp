# Инструменты и настройки

## Чтение

| Инструмент | Назначение |
| --- | --- |
| `outlook_capabilities`, `outlook_inspect` | Возможности и доступ выбранного ящика |
| `mail_folders`, `mail_search` | Папки и поиск за явный период |
| `mail_message` | Текст выбранного письма по подписанной ссылке |
| `mail_attachments`, `mail_attachment`, `mail_attached_message` | Метаданные и части выбранных вложений |
| `mail_refresh_reference`, `mail_changes` | Обновление ссылки и инкрементальные изменения |
| `calendar_context`, `calendar_event` | Контекст календаря и выбранная встреча |
| `calendar_freebusy`, `calendar_upcoming` | Занятость и ближайшие встречи |
| `outlook_read` | Дополнительные типизированные операции EWS |
| `outlook_prepare` | Подготовка плана одного изменения |

Каталог не доказывает доступность операции на конкретном Exchange. Возможности
определяются настройками, версией сервера и существующими правами учётной записи.
Microsoft 365 с отключённым EWS/basic/NTLM требует другого способа доступа;
эта версия не реализует Microsoft Graph или интерактивный OAuth.

В списках проверять `complete`, `truncated`, `next_cursor`, `next_offset` и
`caught_up`. Одна страница не равна всем данным за период. Ссылки и checkpoints
не редактировать; для вложений продолжать по смещению и проверять SHA-256.

## Общий ящик

`self` — собственный ящик из `EWS_EMAIL`. Для общего ящика задать точный адрес
в `EWS_SHARED_MAILBOX`, затем использовать `mailbox="shared"`.
У учётной записи уже должны быть выданы соответствующие права Exchange.
Пример не создаёт делегирование и не меняет разрешения.

## Запись

1. Сгенерировать ещё один случайный токен и записать в `EWS_WRITE_API_TOKEN`.
   Он должен отличаться от `BRIDGE_API_TOKEN` и содержать не менее 32 символов.
2. В `EWS_ENABLED_WRITE_GROUPS` явно перечислить необходимые группы:
   `calendar,mail,send,folders,contacts,tasks,settings,subscriptions`.
   Разрешать только нужные конкретной установке.
3. Перезапустить сервер и создать отдельное HTTP MCP-подключение с write-токеном.

Ключ чтения предоставляет 16 инструментов чтения/подготовки; отдельный ключ
выполнения — `outlook_execute`. Готовить план в читающем подключении, проверять
его цель и эффекты, затем выполнять в пишущем с исходным `plan_ref` и стабильным
`request_id`. При неизвестном исходе сверять объект и журнал перед повтором.
Развёртывание коннектора само по себе не поручает отправлять письма или встречи.

## Docker

Compose читает `.env`, публикует `127.0.0.1:8080` и сохраняет состояние в томе
`outlook-state`. Docker Desktop не обязателен. Для EWS/VPN контейнеру нужен
сетевой доступ к Exchange; схема VPN зависит от вашей организации.

При остановленном сервере сохранить приватный `.env` и том состояния. В нём
хранятся ключи подписания ссылок, checkpoints и журнал операций. Не публиковать
его и не смешивать состояния разных пользователей. Команда `docker compose down`
сохраняет том; не добавлять `--volumes`, если данные нужны.

## Проверка подключения

`/healthz` подтверждает работу процесса, а не доступ к почте. Проверить MCP:

```bash
uv run --locked --env-file .env python examples/check_connection.py
```

Скрипт получает каталог инструментов и читает одну страницу папок собственного
ящика. Не отправляет писем и не выводит содержимое папок, сообщений или секреты.

## Частые ошибки

| Ошибка | Что проверить |
| --- | --- |
| Не открывается `/healthz` | Запущен ли процесс, свободен ли порт 8080 |
| MCP возвращает 401/403 | Тот же ли `BRIDGE_API_TOKEN` в клиенте и `.env` |
| EWS Unauthorized / 502 | Новые ли логин/пароль, разрешён ли выбранный способ EWS-аутентификации |
| Timeout / DNS / TLS | Доступ к серверу из среды запуска, VPN и корпоративные доверенные сертификаты |
| Опция выключена | Включить нужный флаг из `.env.example` и перезапустить сервер |

Не отключать проверку TLS для устранения ошибки сертификата. Установить
корпоративный CA в доверенное хранилище своей среды согласно правилам организации.
